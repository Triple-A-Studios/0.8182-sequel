# UI (UI Toolkit)

Project convention: UI Toolkit (UITK), not uGUI (see [CLAUDE.md](../../CLAUDE.md)). This file describes the UI **as it stands at the end of the UI/art pass** (Alpha milestone, branch `milestone/ui-art-pass`, mockups in `Docs/Mockups/`, gap analysis in `Docs/Mockups/gap-analysis.md`). How each screen was built pass by pass is in git history and in the "Decisions of record" and "History" sections at the end; the pre-redesign per-element panels no longer exist.

## At a glance

| Where | Panel (`PanelRenderer`) | Screens |
|---|---|---|
| `Bootstrap.unity` | launch panel (`LaunchFlow` child of `Bootstrap`, sorting order **100**, draws above everything) | loading + rotate-device gate (S01), last week's results (S11) |
| `MainMenu.unity` | menu panel (`MainMenuUI`) | main menu (S02) + attempt / quit / overflow popups, Settings (S06), Leaderboard (S07), Profile (S08), Shop (S09), Credits (S10) |
| `Prototype.unity` (under `HUD`) | `Hud` panel, `GameOver` panel (sorting order 1) | gameplay HUD (S03 a-h) + pause popup / resume countdown (S04), Game Over (S05) |

All four panels share **one** `PanelSettings` asset, `Assets/_Project/Settings/FuelGaugePanelSettings.asset` (Scale With Screen Size, reference **2400x1080**, Match 0.5; the old name stays because every `PanelRenderer` references its GUID). The menu scene is unloaded when a run starts and loaded again by the Daily play structure milestone's flow (Game Over MAIN MENU is still a toast). The game scene is loaded additively by `BootstrapLoader`; running `MainMenu.unity` or `Prototype.unity` on its own works without the launch panel.

## Conventions

- **Panel scripts** use `[RequireComponent(typeof(PanelRenderer))]` (not `UIDocument`, frozen since Unity 6.5): `OnEnable` registers `RegisterUIReloadCallback(OnUIReload)`, `OnDisable` unregisters it; `OnUIReload(renderer, root, version)` runs the `root.Q<>()` queries and may fire more than once per enable, so guard with `if (m_loadedRoot == root) return;`. Subscriptions to game systems stay in `OnEnable` / `OnDisable`. Most screens are **plain classes over their root element** (`SettingsScreen`, `LeaderboardScreen`, `ProfileScreen`, `ShopScreen`, `CreditsScreen`, `LoadingScreen`, `LastWeekResultsScreen`, `HudView`, `GameOverView`), owned by a MonoBehaviour host (`MainMenuController`, `HudHost`, `GameOverHost`, `LaunchFlowHost`) and by the dev gallery drivers, so the same view runs in the game and in the galleries.
- **Naming** follows `.editorconfig` (`m_` private fields, `k_` private consts, `m_S_` private static readonly, UPPER_SNAKE public consts); `.cs` files use tabs. No Alchemy `[ShowInInspector]` debug fields.
- **Reference sizes.** Everything is authored in 2400x1080 reference px. Minimum text size **24 px** (one known exception: the 19 px PROFILE sub-label on the menu chip). Minimum tappable size **80 px** (about 4.7 mm on a 6.4 inch phone, where 1 reference px is about 0.06 mm; the hit area may be larger than the visual).
- **Supported shapes.** The aspect sweep (4:3 up to 22:9; panel sizes from 1800x1350 down to 2514x1029) found no overflow or overlap on any router screen or popup; the supported range is a logical panel height of **1029 px and up**. At 4:3 / 16:10 the Profile has a gap under its badges and "Crop Duster Mk.II" ellipsises (accepted).
- **Uppercase** labels are typed in uppercase (USS has no `text-transform`). **Glyphs** used in production UI are only `· × – ‹ ›` (all present in both fonts, checked against the TTF cmaps); icons that are not text (arrow, pencil, dice, tick, heart, rotate phone, dashed ring) are baked textures tinted in USS, so no font fallback is needed on WebGL.
- **Folders.** `UI/` (UXML / USS per screen, `Theme/Theme.uss`, `Dev/UIGallery.*`, `Hud/Hud.*`), `Scripts/UI/` (`Foundation`, `Hud`, `GameOver`, `Settings`, `Leaderboard`, `Profile`, `Shop`, `Credits`, `Launch`, `Dev`, plus `MainMenuController.cs`), `Art/Fonts`, `Art/Textures/UI`, `Scenes/Dev`.

## Foundation (`Scripts/UI/Foundation`, `UI/Theme/Theme.uss`)

- **Theme.uss** is included by every screen (`<Style src="project://database/Assets/_Project/UI/Theme/Theme.uss" />`, class `theme` on the screen's root). It holds the palette as USS variables on `:root, .theme` (13 tokens plus ink alphas `--ink-70 / -55 / -35`), the default font (Nunito Bold), type roles (`t-logo`, `t-score`, `t-title`, `t-heading`, `t-number(-lg)`, `t-label`, `t-body(-secondary)`, per-weight font classes, `fs-*` sizes), backgrounds (`screen-bg`, `screen-stripes`, `ui-safe-area`) and every component: `.lipbox*`, `.tabbar*`, `.popup*`, `.screen-header*`, `.screen-title(--tilt)`, `.screen-instance`, `.card` / `.card__title` / `.field*`, `.pip`, `.bar`, `.sticker`, `.themed-slider`, `.switch`, `.checkbox`, `.ui-toast*`.
- **Fonts.** Baloo 2 (SemiBold / Bold / ExtraBold: titles, numbers, buttons) and Nunito (Regular to ExtraBold: labels, body, tabs) in `Art/Fonts`, referenced from USS with `-unity-font-definition: url(...ttf)`; UITK cannot pick a weight from one family, so each weight is its own class. The Baloo / Nunito line boxes are much taller than the glyphs: titles and values use fixed heights, one label per line, or negative margins to trim the slack.
- **`LipBox` / `LipButton`.** Structure `.lipbox > .lipbox__lip + .lipbox__face`; the wrapper reserves the lip height as bottom padding and the lip is an absolutely positioned backing element (USS has no `box-shadow`). Variants `Panel`, `Primary`, `Secondary`, `Danger`, `Positive`; lip sizes `Small` 6 / `Medium` 10 / `Large` 14. **The element's height includes the lip.** Children added in UXML or code go inside the face. `LipButton` adds `text`, `clicked` and the press state: `PressedClassManipulator` toggles `is-pressed` on raw pointer events (not `:active`) and USS translates the face down by lip - 4 px (translate, not the mockup's 0.97 scale, after an on-device correction). Disable with `SetEnabled(false)`.
- **`TabBar`**: `choices="A,B"`, `selectedIndex`, `accent` (`Amber` / `Coral`), `changed(int)`; a choice may carry a tag, `"CRASH FX|BETA"`, shown as a `.tabbar__tag` label that hides while the tab is active. `.tabbar__tab` has `min-height: 80`. **`ThemedSlider`**: a `Slider` plus an amber fill kept at the knob; `snapStep` lets knob and fill follow the pointer freely while down and settle on the step on release (trickle-down pointer-up listener plus a 40 ms poll that snaps once no pointer capture is left; snapping inside the value-changed callback pinned the knob). The slider is an **80 px hit area** around a 44 px knob and 20 px track; its empty 24 px above the track tucks under the label row and 14 px below into the next field's margin, so a field costs about 42 px. **Toggles** are the built-in `Toggle` with `.switch` (128 x 80 hit area around the 104 x 56 pill) or `.checkbox` (80 x 80 around its 56 px box); both need explicit `flex-basis` / `min-width` or the default theme collapses their input.
- **`ScreenRouter`** (plain object): `Register(id, element)`, `SetRoot`, `Show` (push), `Back`, `ShowPopup` / `ClosePopup` (one popup at a time inside a `.popup-layer` dim backdrop; a backdrop tap dismisses unless disabled), `HandleBackRequested()` (popup first, then back), `ScreenChanged`. It owns no input: Escape (the Android back button in the Input System) calls it from the host. **Every screen instance must be registered**: an unregistered screen is never hidden and flow children share the safe area's height. `ShowPopup` only hides the popup it closes, so popups start `display: none`.
- **`SafeAreaHelper.Apply(element, basePadding = 24)`** insets a full-screen element by `Screen.safeArea` converted to reference px (`ComputePadding` is the pure maths), on every geometry change **and** on a 250 ms poll of the safe area and screen size (a 180 degree landscape flip keeps the screen size, so no geometry event fires; found on a device). `SafeAreaHelper.SafeAreaProvider` is a test seam. **Rule:** USS absolute offsets are measured from the parent's border box and ignore its padding, so edge-anchored content must live in a *flowing* child of the padded container: the menu's `.menu-screen` is `flex-grow: 1` with `margin: -24px` (the base padding) so its absolute clusters keep their mockup offsets and a device inset adds on top; full screens are `.screen-instance` (`flex-grow: 1`) flow layouts with 16 / 24 px of their own padding; the HUD uses `hud-safe` (absolute fill, `Apply(..., 0)`) around `hud-content`; Game Over uses `go-safe`.
- **`UiToast`** builds its own `.ui-toast` element as the host's last child (centred, or hung `topOffset` px from the top); `Show(message, ms = 2500)` restarts the timer, never takes pointer events. One instance each in the menu (`ARRIVES IN A LATER UPDATE`, `COMING SOON` for HOW TO PLAY), the HUD (top 230 px, under the fuel / health stack), Game Over (top 24 px) and the S11 screen.
- **Textures** (`Art/Textures/UI`, uncompressed, no mipmaps, clamp unless noted), generated by `Tools/generate_ui_textures.py` (Pillow; re-run to regenerate): `Tex_UiBgGradient` (sky), `Tex_UiGradAmber`, `Tex_UiBgStripes` (repeat), `Tex_UiHazardTape` (repeat), `Tex_UiVignetteRed`, `Tex_UiVignetteDark`, `Tex_UiCracks`, `Tex_UiArrowUp`, `Tex_UiDashedRing`, `Tex_UiPencil`, `Tex_UiDice`, `Tex_UiCheck`, `Tex_UiHeart`, `Tex_UiRotatePhone`; `Tex_Logo.png` is the supplied Triple-A Studios logo (a 2160 px square with the mark in the middle third; cropped in USS with `background-size` / `background-position`).
- **USS limits worked around.** No `linear-gradient()` (baked textures stretched with `-unity-background-scale-mode: stretch-to-fill`; they clip to `border-radius`), no dashed borders (solid thin borders, or the baked dashed ring), no `box-shadow` (backing elements), no `:last-child` or sibling combinators (margin on the following element), a single `text-shadow` (the logo is three stacked labels), no monospace font (Nunito). Stripes use `background-repeat` with an explicit `background-size: 64px 64px`. A rotated element is laid out unrotated (size it, then rotate). `.card` face overrides need a higher-specificity selector (`.lb-own.card > .lipbox__face`). A zero-width container makes UITK wrap labels one character per line (start at 1 px). `ScrollView` needs `flex-basis: 0`. Lip-sized children: translucent faces show the lip through them (flatten to opaque). UITK squashes flex children instead of overflowing, so check for overlap, not only bounds.
- **Panel sharing.** All `PanelRenderer`s on one `PanelSettings` share a runtime panel: a visible full-screen `game-over-root` picks everything, which is why input is dead behind Game Over. `Renderer.sortingOrder` on the `PanelRenderer` orders them (launch 100, Game Over 1, rest 0).

## Launch flow

`UI/Loading.uxml` + `Loading.uss` on the launch `PanelRenderer` in the Bootstrap scene; `Scripts/UI/Launch/`. `BootstrapLoader` loads `MainMenu` and `Prototype` additively, reports `AsyncOperationGroup.Progress` to `LaunchFlowHost` every frame, sets the game scene active, then awaits `LaunchFlowHost.WaitUntilReadyAsync()`; the menu is already loaded and active underneath the opaque panel.

- **Loading (S01).** `LoadingScreen` (view over `launch-root`): wordmark, key-art slot (the studio logo stands in; solid thin frame, dev caption marked for deletion), one random quip (`LoadingQuips`, 12 lines, yours to rewrite), amber progress bar + percentage. `LaunchFlow` holds the rules: `MIN_SECONDS` 1.5 (the screen never flashes), `MapProgress` = raw / 0.9 (`AsyncOperation.progress` stops at 0.9 until activation), `BAR_SPEED` 1.5 per second (a jump to 100% still reads as a fill), `GateApplies()` (mobile, WebGL or the Editor), `CanLeave`. UGS init is not part of the bar. `[Launch] loading screen left after N s` is logged.
- **Rotate gate.** `Screen.height > Screen.width` where `GateApplies()`: the art block is replaced by `Tex_UiRotatePhone` + ROTATE YOUR DEVICE, the bar stays, loads keep running and the hand-off waits for landscape. Loading screen only (in-session rotation needs pause). The layout also holds in a 1080 x 1920 portrait panel. Checked in the Editor, in a local WebGL build with a portrait mobile viewport (holds, releases at landscape); **not** exercised on itch.io (its player page rotates the embed): backlog #29.
- **Last week's results (S11).** `LastWeekResults.uxml` is instanced into `Loading.uxml` as `screen-results` beside `loading-content`. Top-five winners (rows 1-3 tinted, `LeaderboardRow`), the date range of the closed week (the server start and end through `LeaderboardWeek.RangeText(start, end)`), and the player card (`#31`, "of N pilots · top X%", best score, SHARE MY RESULT + CONTINUE; the no-ranked-run variant has "–", no share, neutral border). `LaunchFlowHost` starts `ILastWeekResultsSource.GetPendingAsync()` at boot (it overlaps the loading screen), waits at most 3 s after the minimum time for it, and a result shows the screen (calling `MarkShown()`) and awaits CONTINUE. The shipped source is `LeaderboardLastWeekResultsSource` (stored `lb_last_shown_version`, silent on a fresh install, nothing for a player who never ranked; details in [leaderboard.md](leaderboard.md)); `NullLastWeekResultsSource` stands in without a leaderboard service; `LaunchFlowHost.ResultsSource` can still be set to another. The serialized `Debug Results` field on `LaunchFlowHost` (None / WithRank / NoRank, Editor and `DEBUG` builds only) forces the static sample (`LastWeekResultsPlaceholderData`) through the real flow. SHARE shows the arrives-later toast.

## Main menu and its screens

(`UI/MainMenu.uxml` + `MainMenu.uss`, `Scripts/UI/MainMenuController.cs`.) `MainMenu.uxml` is the root: `screen-bg` + `screen-stripes` + `safe-area` (holding `screen-menu` and the five screen instances `screen-settings`, `screen-leaderboard`, `screen-profile`, `screen-shop`, `screen-credits`), then the router's `popup-layer` (`popup-attempt`, `popup-quit`, `popup-overflow`). Each full screen is its own UXML + USS (`<Style>` inside the template) instanced as `<ui:Instance template="..." class="screen-instance" />`. `MainMenuController` registers every screen on one `ScreenRouter`, opens / closes screens from `ScreenChanged`, and does the routing.

**Menu (S02).** Chips, tiles and PLAY are `LipBox`es with a `PressedClassManipulator`; the mode tabs are a coral `TabBar` bent into tabs behind PLAY (`.menu-mode-tabs`; PLAY has a fixed `min-width`); the title is the 3-layer text trick. COMPETITIVE / PRACTICE swaps the top-left chip (ATTEMPTS pips vs practice clock) and the PLAY sub-label. PLAY in competitive opens the attempt-confirm popup (LET'S FLY, CANCEL, "or fly it in Practice instead", "Don't ask again today" as a static in-session field `m_s_dontAskAttemptConfirm`, deliberately not persisted); in practice it starts the run. Starting a run hides the menu root, tells `GameManager.EnterPlayingState()` and unloads the menu scene. Hamburger opens the overflow dropdown: SETTINGS, CREDITS (screens), HOW TO PLAY ("COMING SOON" toast, Beta tutorial), QUIT GAME (quit-confirm popup; hidden on WebGL; `EditorApplication.isPlaying = false` in the Editor, `Application.Quit()` in players). Escape closes a popup, then goes back; nothing at the root (Escape while renaming only leaves the field). Profile chip opens Profile, the coin chip and SHOP tile open the Shop (coins are earned, never sold: no `+`), the LEADERBOARD tile opens the Leaderboard. A synthetic `ClickEvent` does not toggle a `Toggle`; set `.value` when driving it from outside.

**Settings (S06).** `SettingsScreen` over `SettingsService` (persisted in PlayerPrefs, see [settings.md](settings.md); it replaced the session-only `UiSettingsState`): `Sound` 0-100 (80), `Haptics` (on), `ScreenShake` 0-150 (120), `JoystickSide`, `JoystickSize` step 0-2 = S / M / L, `Sensitivity` 0.5-1.4 in 0.1 (0.9), `InvertSteering`. AUDIO / FEEL / CONTROLS cards plus a live joystick preview: the ring is 150 / 190 / 230 px for S / M / L, `.settings-preview--right` flips the card, the handle follows the pointer scaled by sensitivity and eases back (`.is-dragging` turns the transition off). Every value is applied in play (sound: [audio.md](audio.md); shake and haptics: [haptics.md](haptics.md); joystick side / size / sensitivity and invert: [movement.md](movement.md#touch-control-settings-pause-settings--audio-pass-6)). A slider's release saves the snapped value and ticks (Sound only). The pause popup reads and writes the same service and re-reads it every time it opens (the Settings screen lives in another scene), so the two never disagree; the shake range is 0-150 in both (the mockup fill implied 0-200).

**Leaderboard (S07).** `LeaderboardScreen` (tabs WEEKLY / ALL-TIME, past-week stepper ‹ ›, rows built in code into a `ScrollView`, pinned own row with SHARE MY RANK, loading skeleton / empty / error / offline panels, token-guarded async load) with `LeaderboardWeek` (pure UTC-Monday week maths: `StartUtc`, `ResetText` "N DAYS" then "Xh", `RangeText` from a week index or from a server start / end, `Name`) and `LeaderboardPlaceholderData`. Data comes through a `LeaderboardProvider(tab, weeksBack)` delegate; the default reads the real service for WEEKLY / this week and for ALL-TIME. **Real vs sample:** WEEKLY is the real Top-10 of the weekly board and ALL-TIME the real Top-10 of the all-time board (`GetTopScoresAsync(board, 10)`, cached 90 s by the service); past weeks are the real closed weeks (`GetArchivedWeekAsync`, up to 4): the ‹ › stepper is built from the cached weekly versions (limit = closed weeks, the arrows hidden when there are none or the versions call failed, a week kept by version id), the range comes from the server dates and the reset chip from the board's `nextReset`, neutral (days, hours only on the last day, never minutes, never red or pulsing), FINAL on a closed week. The SAMPLE DATA sticker on ALL-TIME shows only when `LeaderboardPlaceholderData.AllTimeIsSample` is set, and the gallery supplies sample closed weeks through `LeaderboardScreen.VersionsProvider` (its `P` key toggles them). Rows 1-3 are the larger gold / silver / bronze rows (106 px), the rest 84 px; fixed heights. States have no mockup (designed in the empty state's language); the empty state follows the HTML (WEEKLY / ALL-TIME, FLY NOW goes back to the menu, switches to COMPETITIVE and runs the PLAY path), not the stale PNG. See [leaderboard.md](leaderboard.md).

**Profile (S08).** `ProfileScreen`, `UiProfileState` (session-only `DisplayName`, `MAX_NAME_LENGTH` 16, `GenerateName()` "adjective + plane + number", `Sanitize`), `ProfilePlaceholderData` (stats, coins, id line, equipped plane / FX, the 12 badge definitions). Left column: portrait slot + DISPLAY NAME card; right: six stat tiles, EQUIPPED PLANE / CRASH FX cards, badge row (12 tiles in a horizontal `ScrollView`, tap for the unlock condition). Rename: pencil turns the name into a `TextField` (16 chars, selected, focused) with a dice and a tick; Enter or the tick commits (trimmed, controls dropped, spaces collapsed, empty keeps the old name), leaving or Escape drops the edit; the menu chip follows. The name is **session only and not sent to Unity Services** (free text needs moderation, part of "Player profile and run stats"). While editing, `ProfileScreen` polls the keyboard height (`ProfileScreen.KeyboardHeightProvider`, default `TouchScreenKeyboard.area`) and slides the whole screen up until the field sits 24 px above the keyboard, back when it goes away (a phone keyboard covered the field before this; on WebGL the browser pans the page itself, and a browser only raises its keyboard for a tap on the input, so the WebGL hint reads "Tap the name to type · up to 16 characters").

**Shop (S09).** `ShopScreen` + `ShopPlaceholderData`: four plane cards (`ShopCardState` Equipped / Buy / NotEnough / Locked, built in code), PLANES / CRASH FX BETA / BUILDING SKINS BETA tabs (the Beta tabs show a hazard-tape COMING IN BETA banner), coin chip. Static; BUY and EQUIPPED show the arrives-later toast (nothing can be bought; currency is the Beta "Shop, currency, economy" milestone). Thumbnails are empty slots.

**Credits (S10).** `CreditsScreen` + `CreditsContent` (the single block of text and links: **name, links and thanks are placeholders for the developer to fill**; an empty URL keeps a chip visible but inert, an empty label hides it; the menu calls `Application.OpenURL` for a non-empty URL; the version line is the real `Application.version`).

## Gameplay HUD

(`UI/Hud/Hud.uxml` + `Hud.uss`, `Scripts/UI/Hud/`; mockup S03 a-h and S04.) One merged panel (child `Hud` of the `HUD` object in `Prototype.unity`; `PlayerManager.m_hud` toggles it with the run). Everything is `picking-mode: Ignore` except the joystick zone, the pause button, the boost button and (while open) the pause popup / countdown.

- **Layers** (`hud-root`, bottom to top): `hud-input` (full panel, not safe-area inset: the joystick maths is in panel space), `hud-safe` > `hud-content` (safe-area inset: score, practice tag, fuel + health stack, pause, boost, hit sticker, combo sticker), `hud-fx` (damage overlay, ground vignette + PULL UP!), `hud-edge` (ceiling banner, lateral tapes), `hud-popups` (impact popups), `hud-popup-layer` (pause popup), `hud-countdown`; the toast is added last.
- **Code.** `HudView` (pure UI: `SetScore / SetFuel / SetHealth / SetPractice / SetCombo / SetLowFuel / SetLowHealth / ShowDamage / SetCeilingWarning / SetLateralWarning / SetGroundWarning / ShowImpactPopup / SetRunEnded / ShowToast`), `HudHost` (owns the view, rebuilds on reload), `HudPresenter` (in play: binds `FuelSystem`, `HealthSystem`, `ScoreSystem`, `AltitudeSystem`, `LateralSystem`, `PlaneController`), `HudTouchControls`, `HudImpactPopups`, `HudPausePopup`, `HudPlaceholderData`, `Dev/HudStateDriver`. Game-side additions: `AltitudeSystem.CeilingWarningSeconds`, `ICrashSource.WorldPosition`, `ScoreSystem.PointsAwarded`.
- **Fuel** is 10 pips; pip `i` fills `clamp01(fraction*10 - i)` so the boundary pip is partial. **Health** is a fill bar whose colour lerps red to green (red at 25% and below, green at 75% and above). Low fuel (25%) swaps the label to a flashing LOW FUEL on an amber-ringed plate; low health (30%) adds a red halo (presenter tunables). The **combo sticker** shows while the multiplier is above x1 and the timer is live, shrinking to 78%, fading to 70% and desaturating as the timer drains.
- **Warnings.** Ceiling: taped banner slides down with a countdown `ceil(fraction * CeilingWarningSeconds)` and the fuel / health stack shifts down 168 px. Lateral: hazard tape on the offending edge (sign of the plane's x; no countdown, the system has none). Ground: flashing vignette + PULL UP! (0.25-0.85 opacity every 350 ms, a UITK scheduled item on unscaled time). **Effect arbiter:** one full-frame effect at a time (`RefreshFrameEffects`): the damage overlay (dark vignette + cracks, 1.5 s, restarted per hit) shows only while the ground warning is off; the `-N HEALTH` sticker (real HP lost, from a drop in `HealthSystem.HealthValue`) is independent.
- **Impact popups.** `ScoreSystem.PointsAwarded(points, worldPosition, perfect)` after scoring each crash; `HudImpactPopups` keeps a pool of 6 (round robin) and `HudPresenter` converts the world point once at the impact with `RuntimePanelUtils.CameraTransformWorldToPanel` (the plane flies through the point, so tracking would slide it away). Each popup scales 0.5 -> 1.12 -> 1, floats 130 px and fades from `Time.unscaledTime` so hit-stop does not freeze it. The coin line is built but off (`HudPlaceholderData.ShowCoinPopup`).
- **Touch controls.** The floating joystick (left half of the panel; ring 300 px, handle 132 px; `HudTouchControls` raises `SteerChanged` / `BoostChanged`, steer saturates at 50 px of finger travel) and the boost button (186 px circle) feed `PlaneController.TouchSteer` / `TouchBoost` through `HudPresenter` (zeroed on disable). Touch and keyboard / gamepad combine additively (no platform branching).
- **Run end.** `HudView.SetRunEnded(true)` clears the warnings and keeps them off, releases and disables the joystick and boost and the pause button; the HUD stays visible dimmed behind Game Over.
- **Pause popup + resume countdown (S04).** `HudPausePopup` (`HudView.PausePopup`): PAUSED card with SOUND / SCREEN SHAKE sliders and a HAPTICS switch (shared `SettingsService`), RESUME / RESTART RUN / QUIT TO MENU; the popup opens with `dismissOnBackdrop: false`. `HudPresenter` opens it from `GameManager.Paused`; RESUME runs the 3-2-1 GET READY on unscaled time (derived from the clock, one scheduled item) and the game unfreezes at `CountdownFinished`; RESTART RUN is `GameManager.RestartRun()`; QUIT TO MENU opens the leave-run confirm in a competitive run (`hud-leave-popup`, same popup layer) and runs the toast stub in a practice run (`GameManager.IsPracticeRun`). `HudView.PauseOpensPopup` is now only the HudGallery's switch. Pause, auto-pause and the portrait overlay: [game-flow.md](game-flow.md#pause-pause-settings--audio-pass-2a).

## Game Over

- **Files** (`UI/GameOver.uxml` + `GameOver.uss`, `Scripts/UI/GameOver/`; mockup S05 a / b / c). `GameOverView` (pure UI), `GameOverHost` (owns the view), `GameOverUI` (in-play presenter: the `RunEnded` subscription from `Start` and `OnEnable`, the token-guarded leaderboard submit and Retry, the buttons), `GameOverPlaceholderData`, `Dev/GameOverStateDriver`. `GameManager.RunEnded` carries a `RunEndCause` ([game-flow.md](game-flow.md)); the cause chip reads OUT OF FUEL / WRECKED / FLEW TOO HIGH / HIT THE DECK / OUT OF BOUNDS. The panel is a separate `PanelRenderer` (sorting order 1) with `GameOverUI.m_scoreSystem` wired in the scene.
- **Layout.** A full-panel backdrop (picks pointer events) holding `go-safe` > `go-content`, a centred flex column (title + cause chip, FINAL SCORE, four stat chips, rank chip, button row; `justify-content: center`, 24 px above the buttons); flow layout, every block `flex-shrink: 0` (UITK would otherwise squash the cause chip).
- **Rank chip** (one chip, several states, each starting from `ResetRankChip()`): `ShowRanking()` (skeleton pulsing on a 520 ms scheduler item), `ShowRankResult(rank, improved, delta, caption, status, style)` ("#N", a green up-arrow **image**, optional divider + status; a worse or equal rank shows the number alone, never red), `ShowRankUnranked`, `ShowRankMessage(message, showRetry)` (submit failed + RETRY, leaderboard unavailable), `HideRank()`. In play only what the game knows is shown (hidden for zero score, RANKING, ranked, failed, unavailable; no place count because `SubmitResult` carries none); provisional / final / unranked-with-gap are gallery samples and the in-play status text is placeholder. An improved rank counts down to its number (the cascade waits until the chip has faded in), then the caption and tail widen; the target width is **measured from the text**, not read from the layout (the laid-out width is squeezed while the container is clamped, which caused a stutter). Everything inside the clamped containers needs `flex-shrink: 0`.
- **Entry cascade** (`Show(animate: true)`): one 16 ms scheduled item drives every piece from unscaled time (title pop 0.2 s, score slam + count-up 0.95 s, stat chips pop from 0.35 s 60 ms apart with EARNED counting, rank chip fade from 0.75 s, button row rises from 0.6 s on its own clock); the clock starts on the first tick (a long first frame must not eat the animation). NEW BEST! slams in last, absolutely positioned off the right of the score column so the score stays centred.
- **Buttons.** Five fixed `LipButton`s whose label and action id are set per attempt state (`GameOverAttemptState`: `PlacedWell` BANK IT primary, `DidNotPlace` RETRY primary, `FinalAttempt` LEADERBOARD primary + greyed PRACTICE, `Practice` with a PRACTICE tag on SHARE); one `ActionClicked(GameOverAction)` event. **In play only RETRY / RETRY NOW is real** (reloads the active scene); BANK IT, PRACTICE, MAIN MENU (a real return-to-menu is the Daily play structure flow; reloading Bootstrap would re-run `BootstrapLoader` and risk duplicating UGS init), LEADERBOARD and SHARE show the arrives-later toast. Stat chips, the "2 attempts left today" note and NEW BEST! / YOUR BEST are placeholders in `GameOverPlaceholderData`.
- Chips, stickers and popups use `LipBox` lips (uniform border on the face, lip as the backing element), not thick bottom borders.

**Driving the UI from outside the Editor (Unity CLI).** A backgrounded Editor does not advance play mode: set `Application.runInBackground = true` in the eval script. `simulate_pointer` stops delivering after the first click and uses bottom-left pixel coordinates; dispatch `ClickEvent.GetPooled()` with `target` set (a synthetic `ClickEvent` does not toggle a `Toggle`). Screenshots: schedule `ScreenCapture.CaptureScreenshot` inside the panel's scheduler (CLI calls are slower than 2.5 s toasts and the animations). Editing USS / PNG assets from outside needs `AssetDatabase.Refresh()` and a new Play; editing a UXML while in Play can blank the panel. Reflection reaches private state (`m_loadedRoot`, `m_router`). A fixed-resolution Game view reports a bogus `Screen.safeArea` (a Simulator-mode Game view reports a real notch). Aspect sweeps: set fixed Game view sizes, show each screen, wait a frame, then scan the visual tree for elements outside their screen, overlapping flow siblings, targets under 80 px and text under 24 px. `TextField` input in a WebGL build needs real key presses (the browser tool's text insertion is ignored by Unity).

## Device and platform notes

- **Android** (verified on a Realme 8s 5G, native build): landscape only, `androidRenderOutsideSafeArea` on (so the inset path is exercised), IL2CPP / ARM64, min SDK 26. Touch feel, glyphs, back button, notch in both landscape directions and the rename keyboard were checked. Back button = Escape.

The project builds with Brotli and no decompression fallback, so an itch upload may need Gzip or the fallback; the default template fixes the canvas at 960x600 on desktop and fills the window only on a mobile user agent; a WebGL build rewrites the tracked `Data/Plugins/lib_burst_generated.wasm` (restore with `git checkout`).
- **Rotate gate on a phone (verified 2026-10-17, backlog #29):** itch.io player forced to portrait on Android shows the prompt.

1. **Pause button (Pass 4):** visible but inert (toast); popup and countdown verified in the gallery only; no `timeScale` pause in this milestone. *Superseded by Pause, settings & audio Pass 2a: pause is real.*

6. **Settings joystick preview (6a):** follows the controls (size, side, sensitivity, snaps back); no drag-to-set-side.

## History (short)

The UI was built in eight passes on `milestone/ui-art-pass`: 1 mockup review, 2 foundation (theme, components, router, safe area), 3 main menu, 4 merged HUD (4a-4g) + pause visuals, 5 Game Over (5a-5c), 6 Settings / Leaderboard / Profile, 7 Shop / Credits / Loading + rotate gate / Last week's results, 8 hardening (shared toast, menu safe area, 80 px targets, aspect sweep, device pass); the frozen pass table with commits is in [progress.md](../progress.md). Before it, the prototype had one `PanelRenderer` per HUD element (`FuelGaugeUI`, `ScoreUI`, `AltitudeWarningUI`, `LateralWarningUI`, `HealthGaugeUI`, `TouchControlsUI`, `GroundWarningUI`) plus a minimal menu, Top-10 popup (`LeaderboardPanelUI`) and Game Over panel; all of those scripts, UXML / USS and scene objects are deleted. The `UIDocument` -> `PanelRenderer` migration (Alpha "MVP bug fix" milestone) and the `GameOverUI` re-subscription fix (it must subscribe to `RunEnded` in `OnEnable` as well as `Start`, because `HUD` is toggled across the Bootstrap menu / play transition) carried over unchanged. The floating joystick (zone in the left half, base positioned at the first touch) replaced the static one in the same milestone; a player-facing side / size / sensitivity option is backlog #25.
