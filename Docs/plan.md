# Plan

## Phases

### Phase: Prototype
Milestones:
- **Core loop, bare minimum** — plane movement, joystick steering, one building type (normal only, weak-point crash), fuel gain/loss, run ends when fuel hits zero, minimal UI (fuel gauge only). Purpose: validate that flying and crashing feels good before anything else is built.
- **Building types + scoring** — adds tough buildings, the boost mechanic, health as a second resource (from mistimed tough-building crashes), and a simple visible score. Prototype is considered done here — the full core resource loop (fuel + health + score) is playable.

### Phase: MVP
Milestones:
- **Obstacles, combos, recovery** — adds the two-tier obstacle system (large obstacle buildings, small hazards like birds), combo chain scoring, and health pickups to recover from bad crashes/obstacle hits.
- **Core systems refactor** — pays down architecture debt flagged during the previous milestone before more features (difficulty ramp, spawning) pile onto it. Replace per-instance `IDamageDealer`/`Crashed` array wiring with a static/global event, since hand-wired arrays don't scale to procedurally spawned obstacles/hazards. Introduce an overseeing `GameManager` (or equivalent) for run/game state. Introduce a `PlayerManager` (or equivalent) that owns crash/damage/run-end orchestration, subscribing to sources and telling `FuelSystem`/`HealthSystem` what to apply — those two become pure resource managers (apply deltas, raise a "depleted" event) with no knowledge of where penalties/refuels come from. Done when obstacle spawning (next milestone's difficulty ramp) has a clean event-driven foundation to build on, and Fuel/Health/Score no longer hand-track source arrays. See progress.md backlog for the individual flagged items.
- **Movement & fail-state rework** — addresses backlog items that don't depend on the difficulty-ramp spawner, ahead of it. Pitch (W/S) becomes purely cosmetic — actual vertical movement uses `rb.linearVelocity` directly, mirroring how horizontal/yaw movement already works, and releasing the input returns both velocity and cosmetic pitch to level. Crash-quality formula gets simplified (currently speed × angle-into-weak-point) so players don't have to reason about precise crash angles — exact replacement formula TBD, decided once the movement change lands and shows what data ("angle" becomes constant) is actually still available. Adds upper/lower altitude bounds as new fail states: a ceiling warns the player before ending the run (plane flies off into the sky, camera stops following), the ground ends the run instantly with the same "blast" treatment as a building crash or a health-zero death — both need a minimal Game Over screen, which doesn't exist yet for any run-end today. Also folds two small independent bugs: the plane momentarily stopping on crash before `Destroy` runs (both are colliders, physics resolves impact first), and Alchemy `[ShowInInspector]` debug fields not refreshing live in Play Mode. Done when movement/crash-quality/altitude-bounds are playable and a Game Over screen appears on every run-end. See progress.md backlog for the individual flagged items.
- **Difficulty ramp** — obstacle/building density and toughness increase over the length of a run.
- **Feel polish** — closes out MVP with the remaining structural and feel gaps: lateral (sideward) run bounds mirroring `AltitudeSystem` (soft warning limit, hard game-over limit — folds backlog #18); a health HUD element mirroring `FuelGaugeUI` (folds backlog #16); on-screen mobile touch controls (joystick + buttons) for the Android build; a main menu scene (UITK, placeholder UI — player name field, Play button, real visuals deferred to the Alpha UI/art pass); the splash → main menu → game scene flow connecting them (own splash scene replaces the Unity splash once built, otherwise Unity's default splash stands in); a revisit of the difficulty-ramp spawn algorithm (folds backlog #17); and camera effects/general juice (shake, follow-tightening on boost, etc.). MVP is considered done here.

### Phase: Alpha
Milestones:
- **MVP bug fix + backlog + engine upgrade** — closes out issues found testing the MVP Android build before Alpha feature work starts. Evaluate the Unity 6.6 upgrade (better UITK support) and decide go/no-go. Fix three Android-only bugs: Game Over screen not appearing on run-end, main-menu stub-button press effects not visible, and a one-off unrecoverable 360°-roll when a finger slides off-screen mid-steer (needs ADB logcat repro). Two QoL items: update Panel Settings target resolution/aspect ratio off the outdated 1920x1080/16:9 assumption (visual polish itself deferred to the Alpha UI/art pass), and rework the static bottom-left touch joystick into a floating joystick (origin follows first-touch position; which screen half is enabled is a later-pass setting). Folds backlog #22 (low-altitude warning, mirrors `LateralSystem`) and #15 (healing building type). Done when the 6.6 decision is made and recorded, all three bugs are fixed and verified on an Android device, both QoL items have landed, and backlog #22/#15 are resolved.
- **Live leaderboard** — Unity Leaderboards (UGS) with anonymous sign-in, decided in Pass 1 research (see `design-doc.md`). Board is a daily-reset (00:00 UTC) Best Score board. Passes: 1 backend research, 2 UGS spike, 3 `LeaderboardService` + submit + Game Over rank with up/down trend, 4 minimal menu Top-10 panel + offline/error states (display-name field deferred to the UI/art pass). Done when a run's score can be submitted and the top scores displayed, verified on Android and in a WebGL build. **Follow-up (2026-10-07): the daily board is being replaced by a weekly (archived) + all-time structure, with a "last week's results" screen — tracked as backlog #28, not yet scoped; see `design-doc.md` > Leaderboards & daily attempts.**
- **UI/art pass** — replace the prototype's placeholder visuals with the developer-supplied mockup (`Docs/Mockups/`; required-vs-available breakdown in `Docs/Mockups/gap-analysis.md`). UI only: the 3D art was split out into its own milestone (next entry) on 2026-10-17 because of its size. **UI scope rule: visuals plus a placeholder-data shell** — any screen/element whose underlying system is a later milestone (attempts, practice clock, currency, shop, profile stats/badges, settings values, pause logic, monthly/all-time boards, share) is built as UI only with static data; the real systems live in the milestones below. Cut from the mockup: the "LV 14" player-level text (no experience system planned). Key art: the supplied Triple-A Studios logo stands in on the loading screen until real key art lands; the game title stays a text wordmark. The 3D slots (menu plane, Profile portrait and thumbnails, Shop thumbnails, loading key art) are built as empty, captioned placeholders for the 3D art pass. Passes (drafted 2026-10-07; frozen table with commits in `progress.md`): 1 mockup review (gap analysis — done); 2 UI foundation (fonts, shared theme + components, screen router/popup layer, safe-area helper, background approach, component gallery); 3 main menu (S02) + overflow menu, attempt-confirm and quit-confirm popups; 4 merged HUD panel (S03 a-h) + pause popup visuals (S04); 5 Game Over (S05 a/b/c, folds backlog #26); 6 Settings (S06), Leaderboard (S07) and Profile (S08) screens; 7 Shop (S09), Credits (S10), Loading + rotate gate (S01) and Last week's results (S11); 8 UI hardening (Android + WebGL + aspect ratios, cleanup of the old UI, `ui.md` rewrite). Done when every mockup screen exists as UITK UI matching the mockup (placeholder data where the system is a later milestone), the old prototype UI is deleted, and it is verified on Android and WebGL.
- **3D art pass** *(not yet scoped)* — replace the prototype's primitive 3D (grey-box plane, buildings, obstacles, ground and sky) with final art and fill every 3D slot the UI/art pass left empty: the menu's rooftop plane, the Profile turntable portrait and equipped plane / crash FX thumbnails, the Shop plane thumbnails, real loading key art (replacing the studio-logo stand-in); plus the takeoff transition (entirely 3D), smoke / plane-wear damage VFX and the crash effects. Done when every 3D asset in the game and every UI slot shows final art, verified on Android and WebGL (mobile performance and build size included).
- **Daily play structure** — (also moves leaderboard score submission behind Cloud Code validation, client submit disabled — see `design-doc.md`) 3 leaderboard attempts/day, a separate practice mode with a hard 30-minute/day cap (exact enforcement mechanics TBD), and a share-to-socials feature for posting a high-score screenshot. Also makes the mockup's attempts chip, mode-tab swap, attempt-confirm and BANK IT / RETRY logic real, and settles the day-boundary/time-source enforcement for the 3 attempts/day (max 21 a week; unused attempts never bank). Builds on the weekly + all-time leaderboard rework (backlog #28), which supplies the boards; share is always opt-in and the UX "don'ts" in `design-doc.md` apply. *Not yet scoped.*
- **Pause, settings & audio** — functional pause, settings screen and pause popup wired to real values and persisted locally (PlayerPrefs, no cloud), and the audio system (SFX only, no music or BGM: a design choice) with generated stand-in clips. Folds backlog #25 and the in-session portrait prompt (ui.md decision 11). Branch `milestone/pause-settings-audio`. Passes (scoped 2026-10-17): 1 settings store (PlayerPrefs-backed `SettingsService` replaces `UiSettingsState`'s session-only backing; UI keeps the same properties); 2 functional pause, split into sub-passes (2026-10-17): **2a core pause**: `GameManager` gets a `PausedState` as the sole orchestrator (`Pause()` / `Resume()`, `Paused` / `Resumed` events, `IsPaused`; Paused to Playing must not re-raise `RunStarted`; `Pause()` ignored unless Playing with the run active and no countdown); only that state's `OnEnter` / `OnExit` touch `Time.timeScale` (0 and 1); `CameraJuice` hit-stop skips its `timeScale` restore while paused; `GameManager.RestartRun()` (resets `timeScale`, reloads the scene) shared by Game Over RETRY and the pause popup RESTART, and `GameManager.Awake` resets `timeScale` to 1 as a safety net; `HudView.SetPaused` releases the joystick / boost and disables the pause button; `HudPresenter` wires pause button, popup, RESUME with the 3-2-1 on unscaled time (the game unfreezes at `CountdownFinished`), RESTART, and Escape / Android back (opens the popup while playing, resumes with the countdown while it is open, ignored during the countdown); the pause button's "arrives later" toast goes away. **2b quit to menu stub and practice branching**: `GameManager` serialized `m_isPracticeRun` (default false, exposed as `IsPracticeRun`, Inspector-toggled for testing; Daily play structure feeds it later; replaces `HudPlaceholderData.IsPractice`); a leave-run confirm popup in the HUD; competitive run: QUIT TO MENU opens the confirm (the attempt is lost without submitting the score) and LEAVE runs the stub; practice run: QUIT TO MENU runs the stub directly; the stub shows the shared "arrives later" toast and returns to the pause popup (the game stays paused); the popup's mode line and quit note follow `IsPracticeRun` (attempt number stays placeholder); HudGallery key for the confirm. RESTART RUN has no confirm until attempts are real (Daily play structure); 3 auto-pause and in-session portrait prompt (scoped 2026-10-22): `GameManager` subscribes to `Application.focusChanged` and pauses immediately on focus loss (the Playing to Paused transition is processed inside the call, because `Update` does not run in the background and the first frame back could otherwise step up to 0.33 s of plane movement; Android home / shade, WebGL tab switch or canvas blur), guarded like `Pause()` and off in the Editor unless a serialized `m_autoPauseInEditor` is ticked; `HudPresenter` cancels a running resume countdown on focus loss and reopens the pause popup (the countdown runs on unscaled time and would otherwise finish unseen on return); a full-panel `hud-rotate` overlay in the HUD (ROTATE YOUR DEVICE, same copy and icon as the loading prompt) shows while the screen is portrait where `LaunchFlow.GateApplies()` and the HUD is active, pausing immediately, cancelling the countdown and ignoring the back key, and hiding when landscape returns with the pause popup still up (the player taps RESUME); gameplay only (menu and Game Over stay ungated, ui.md decision 11); HudGallery key `N` toggles the overlay; 4 audio system (mixer with Master + SFX, `AudioManager` with a pooled SFX player, an editor tool generating placeholder WAV one-shots into `Audio/Placeholder`, Sound slider drives Master, SFX wired to crashes, damage, pickups, warnings, boost, UI clicks and run end, SFX group paused with the game); 5 haptics service (Android vibrate on crash / damage, no-op on WebGL or when off) and the screen-shake slider scaling `CameraJuice` (0-150%); 6 joystick side / size / sensitivity into `HudTouchControls` plus invert-steering in the plane input, settings screen and pause popup staying in sync (folds #25); 7 hardening (Android + WebGL: audio unlock on WebGL, pause edge cases, `timeScale` leaks) and docs (`ui.md`, `camera-feel.md`, `game-flow.md`, new `audio.md`, placeholder registry, backlog). Order 1-7; passes 4-6 are independent once 1 lands. Done when pause, every settings value and the SFX are real and persisted, verified on Android and WebGL. Real return-to-menu stays with Daily play structure.
- **Player profile & run stats** *(not yet scoped)* — generated display name + inline rename (UGS player name; replaces the display-name field deferred from Live leaderboard), persisted lifetime stats (high score, distance, buildings down, best combo, runs, perfect crashes), run-end cause (`GameManager.RunEnded` carries none today) and per-run stats (distance, buildings flattened, best combo) feeding the Game Over screen and a NEW BEST detection, and the 12-badge set. Profile and Game Over screens from the UI/art pass show placeholder data until this lands.

### Phase: Beta
Milestones:
- **Shop, currency, economy** — unlockable planes, crash effects, building skins, funded by an in-game currency earned from crashes. Guardrail: attempt/time caps from Alpha stay un-monetized. The shop screen, currency chip and earned-coin popups exist as UI shells from the Alpha UI/art pass; this milestone makes them real (currency earn/spend, purchases, unlock conditions, equipped plane/FX, more than one plane).

Milestones:
- **Polish pass** — polished, complete version of everything above. No additional major systems currently planned beyond what Beta introduces.
