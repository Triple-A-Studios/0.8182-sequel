### Scoped passes — Movement & fail-state rework
1. ~~**Pitch-cosmetic / velocity-based vertical movement**~~ — Landed `a5f58c0`. `m_verticalSpeed` drives real vertical velocity directly (mirrors `m_sideSpeed`); pitch is now purely cosmetic via a `MoveTowards`-driven angle on `m_visualRoot`, mirroring the existing bank pattern exactly — combined into one `Quaternion.Euler(pitch, 0, bank)` assignment. `m_rigidbody.MoveRotation` and `m_pitchDeg` are gone; the Rigidbody no longer physically rotates at all. `m_pitchRateDegPerSec` renamed to `m_pitchSpeedDegPerSec` (`[FormerlySerializedAs]` preserves the prefab's tuned value). See [movement.md](technical-design/movement.md) for the rewritten spec.
2. ~~**Crash-quality formula rework**~~ — Landed `cd40dcd`. Formula: speed-only, gated on hitting the weak point (`quality = hitWeakPoint ? speed01 : 0f`), dropping the angle-alignment term entirely since cosmetic-only pitch (Pass 1) made angle unreadable by feel. `WeakPoint.OutwardNormal` removed as dead code. See [building-crash-system.md](technical-design/building-crash-system.md#crash-quality-formula). Verification also caught in-editor tuning: plane collider box->capsule, forward speed 20->25, `Building_Normal.referenceMaxSpeed` 25->10.
3. ~~**Minimal Game Over screen**~~ — Landed `2f2e1b4`. `GameOverUI` (`Assets/_Project/Scripts/UI/GameOverUI.cs`) subscribes to `GameManager.RunEnded` — previously had zero subscribers. Shows "GAME OVER" + frozen final score (read once from `ScoreSystem.CurrentScore`) + Restart button (full scene reload via `SceneManager.LoadScene`). Mirrors `FuelGaugeUI`/`ScoreUI`'s UITK pattern. **Caught in testing:** must subscribe to `GameManager` from `Start()`, not `OnEnable()` — Unity only guarantees Awake-before-Start across objects, not Awake-before-OnEnable, so `GenericSingleton`'s instance wasn't always set yet. See [ui.md](technical-design/ui.md#game-over-screen-movement--fail-state-rework-pass-3).
4. ~~**Altitude bounds**~~ — Landed `d76fd2e`. New `AltitudeSystem` (`Assets/_Project/Scripts/Altitude/AltitudeSystem.cs`) is a pure sensor, sibling on `Plane`: `GroundHit` (instant, Y-threshold) routes to `PlayerManager`'s existing freeze-in-place handler; `CeilingExceeded` fires after a pausable warning countdown expires and routes to a new `HandleCeilingExceeded` that disables `PlaneController` + the follow camera's `CinemachineFollow`, deliberately leaving `linearVelocity` untouched so the plane keeps drifting in whatever direction it was already moving (no forced upward launch — a direct correction from the first pass at this). Warning countdown pauses (not resets) while actively descending, only fully resets back in safe bounds. New `AltitudeWarningUI` HUD element for the countdown. See [altitude-system.md](technical-design/altitude-system.md).
5. ~~**Crash-stutter physics fix**~~ — Landed `875f6d9`. `Building`'s `BoxCollider` is now a trigger (`Building.OnTriggerEnter` replaces `OnCollisionEnter`) — trigger overlaps skip PhysX collision resolution entirely, so there's no stopping impulse left to cause the stutter. `other.attachedRigidbody.linearVelocity` replaces `collision.relativeVelocity` (exact equivalent — building has no Rigidbody, so its velocity is always zero); `other.ClosestPoint(m_weakPoint.Position)` replaces the old collision contact point. `ObstacleBuilding` untouched (never destroys itself, no timing race to fix, solidity intentional). Resolves backlog #1. See [building-crash-system.md](technical-design/building-crash-system.md#trigger-based-detection-pass-5).
6. ~~**Alchemy debug-inspector refresh fix**~~ — Landed `b7a8725`. Root cause known but out of scope (Alchemy repaint bug); resolved instead by dropping the standing reliance on `[ShowInInspector]`/`[ReadOnly]` for debug-only variables — removed across `Building`, `AltitudeSystem`, `FuelSystem`, `HealthSystem`, `ScoreSystem`, `GameManager`, `PlayerManager`, `PlaneController`. Fields still used in logic stay as plain private fields (still inspectable via the Inspector's Debug mode); fields that were purely write-only debug output (`Building._lastCrashQuality`/`_lastHitWeakPoint`) and unused debug-only properties (`FuelSystem.CurrentFuel`, `HealthSystem.CurrentHealth`, `ScoreSystem.CurrentComboTimer`) were deleted outright. `ScoreSystem.CurrentScore`/`CurrentMultiplier` and `GameManager.IsRunActive` kept as plain properties — genuinely consumed elsewhere (`GameOverUI`, `ScoreUI`, `HandleRunEnded`), just no longer Inspector-decorated. Standing convention going forward: don't use Alchemy's debug-display attributes at all. Resolves backlog #8.
