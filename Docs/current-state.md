- **Working tree:** `Data/Plugins/lib_burst_generated.wasm` is rewritten by every WebGL build (`git checkout` restores it); the Editor also rewrites `UniversalRenderPipelineGlobalSettings.asset` now and then. Neither is part of the work.
- **Before you test:** reload the open scene after script changes before entering Play Mode. Editor is Unity 6000.6.3f1 (the active build target is WebGL; switching re-imports). All UI scripts use `PanelRenderer`, not `UIDocument`. The saved Sound setting persists between runs, so a silent Editor usually means Sound is 0. Haptics only vibrate on an Android player (`Haptics.Requested` shows them in the Editor); screen shake and joystick settings apply from the next shake / touch. Focus-loss auto-pause is off in the Editor unless `Auto Pause In Editor` is ticked on the `GameManager`; `Is Practice Run` there flips a run to practice (set it before Play). The leaderboard needs a linked Unity Cloud project and the `weekly_scores` / `alltime_scores` boards ([leaderboard.md](technical-design/leaderboard.md)); the Editor and Development Builds use the `dev` environment, release builds `production`. Tools > Daily Play > Reset Today's Attempts And Practice Time restores the day's counters for testing. A WebGL Build And Run uses a new localhost port per build, which looks like a new anonymous player each time (dev-only). An Android build uses the custom main manifest in `Assets/Plugins/Android/` (re-copy Unity's template and re-add VIBRATE + INTERNET when the editor version changes). The dev scenes in `Scenes/Dev` (`UIGallery`, `MenuScreensGallery`, `HudGallery`, `GameOverGallery`, `LaunchFlowGallery`) are not in Build Settings; their hotkeys are listed in `ui.md`. Tools menus for the Player profile systems: `Tools > Player Stats` (log, sample runs, reset), `Tools > Profile Name` (log, reset, sync) and `Tools > Badges` (log, picks, evaluate, big sample run, unlock ALL STAR, reset), `Tools > Planes` (create or update the catalog, log the equipped plane, equip the next plane, reset); `Tools > World > Build Ground Tile` (rebuilds the merged ground tile from `Prefabs/Misc/Ground.prefab`, then the side dressing) and `Build Ground Dressing` (the dressing only); the equipped plane is also local `PlayerPrefs`; the badge, stats and name data are local `PlayerPrefs`, so a reset in one place does not touch the others (Reset Badges keeps the stats, Reset Stats keeps the badges). Development Android builds are minified (R8): a Java plugin that C# calls by name needs a keep rule in `Assets/Plugins/Android/proguard-user.txt` (see share.md). The Android bundle ids differ between development and production builds.
